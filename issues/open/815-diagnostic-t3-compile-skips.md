# 815 — Diagnostic/T3 compile skips

## Summary

49 fixtures are skipped in the diagnostic parity and T3 compile checks.
These fixtures have missing diagnostics or incomplete compile paths in
the selfhost compiler.

## Exact failure scope

- 23 T3 compile skips: fixtures listed in `scripts/check/check-t3-wasm-validate.py`
  `T3_COMPILE_SKIP` and fixtures that time out during compilation.
- 26 diagnostic parity skips: fixtures in `scripts/selfhost/checks.py`
  `DIAG_PARITY_SKIP` plus fixtures whose `.diag` golden file is not yet
  present.

## Machine-readable baseline

The skipped fixture IDs are captured in the verify full receipt
(`docs/data/verify-full-receipt.json`) under `checks[]` where
`check_id == "t3_wasm_validate"` or `check_id == "diag_parity"` and
`items[]` where `result == "skip"` and `owner_issue == "815"`.

The receipt is generated by `scripts/gen/write-verify-receipt.py` from
`python3 scripts/manager.py verify full` output.

## Owner

compiler team (diagnostics + wasm backend)

## Removal condition

Each skip is removed when the selfhost compiler implements the missing
diagnostic or compile path for that fixture. The fixture is removed from
the skip list and runs as a normal check.

canonical i32 widths with the module's memory64 i64 scalar domain. Under
wasm32-gc the wrapper's aux locals (loop counter, result pointer, scratch
tag/length) were declared i32 while every emit_i32_* helper emits widened
i64 ops under memory64, canonical params were read into i64 arithmetic
without i64.extend, local.get of widened aux locals fed i32-expecting
canonical results, and emit_i32_const emitted i64.const for the
memory32-ABI cabi_realloc operands. src/compiler/wasm/p2_canonical.ark
now declares the aux locals i64 under memory64, widens canonical params at
i64-domain reads, narrows results and realloc operands back to the
canonical i32 boundary (emit_canon_i32_const, emit_p2_canonical_result_ptr),
and widens cabi_realloc results into the aux locals. All five
component/resource_v3/* fixtures compile and pass wasm-tools validate
--features gc; T3_COMPILE_SKIP is empty. The remaining count is the one
diagnostic skip below.

Progress (2026-10-11): `diagnostics/mismatched_arms.ark` unskipped.
The typechecker now unifies match arm body types (previously the first
arm's type silently won), and `()`-literal TUPLE-0 is canonicalized to
UNIT in `unify` so `=> panic(...)` / `=> ()` arms agree. The fixture
reports E0200 `type mismatch: i32 vs String` via `.selfhost.diag`.
Verified by: s2->s3 compile of the full compiler (fixpoint s3 produced),
a 611-fixture `check` sweep over all match-using run:/diag: fixtures
with zero new failures, and targeted probes for TUPLE-0/UNIT cases.

Note: a stricter `should_prefer_annotation` variant (erroring on
concrete init-vs-annotation type-arg mismatches, which would also fix
`comprehen_deny_elem_type_mismatch`) was tried and reverted: stdlib and
compiler internals rely on annotation-override where generic inference
is weak (e.g. `let rebuilt: Vec<String> = Vec::from_iter(..)`,
`let ks: Vec<K> = self.keys()`), so enforcing it requires the #912-class
inference work first.

Progress (2026-10-11, cont.): `selfhost/trait_ambiguous_bound.ark`
unskipped; DIAG_PARITY_SKIP is now empty. Generic calls whose inferred
type variable is unreachable from the instantiated return type and every
argument type now report E0200 `cannot infer type parameter T in call F`
at the call — the variable can never be constrained downstream, so the
call previously monomorphized silently with a meaningless type argument.
Vars still mentioned in the return or arguments stay deferred (the
`let v: Vec<i32> = Vec::new()` and `None`-with-annotation paths keep
working). Verified by an s2->s3 compile of the full compiler (fixpoint s3
produced, zero new diagnostics on compiler source).
